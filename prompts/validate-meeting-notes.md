# Validate Meeting Notes

Take the raw meeting notes below and structure them into the following format.

## Decisions
What was agreed or confirmed during the meeting. Each decision is one clear statement. If a decision has a rationale, add it in brackets.

## Action Items
Tasks assigned during the meeting. Format each as:
`[ ] [Owner] — [What needs to be done] — [Deadline if mentioned]`

## Requirements
Functional or non-functional requirements identified or clarified during the session. Write each as a plain numbered statement. Implementation-agnostic, no FE/BE split.

## Open Questions
Unresolved questions that need follow-up. Format each as:
`[ ] [Question] — [Who should answer] — [Urgency: MUST resolve before next session / ASYNC OK]`

## Rules
- Use only what is in the notes. Do not invent, assume, or add context.
- If something is unclear, flag it as an open question, not a decision.
- Apply the project glossary when naming features, roles, or system components.
- If a section has no items, write "None identified."
